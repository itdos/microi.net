# 候选确认协议

> 适用范围：账号、分类、位置、音乐、商品、合集、活动、话题、群组、发布时间、发布通道、草稿类型等存在多个候选或语义歧义的场景。

AI Agent 的默认策略是：能确定的自动补齐，影响写操作且不唯一的必须确认。

## 必须确认的场景

- 多个 `status=1` 或 `loginStatus=1` 的账号可用，用户没有明确指定账号。
- 查询分类、位置、音乐、商品、合集、活动、挑战、群组等返回多个合理候选。
- 用户给出的名称只命中部分结果，或多个候选名称相近。
- 用户提到“草稿”，但无法判断是蚁小二内部草稿还是平台草稿。
- 用户提到“本机发布/本地发布/客户端发布”，但没有可用 `clientId`。
- 用户的发布时间、发布平台、发布类型或账号归属存在歧义。

## 可以自动选择的场景

- 只有一个可用账号，且用户没有指定其他账号。
- 用户提供了唯一稳定 ID，例如 `platformAccountId`、分类 ID、商品 ID 或资源 key，并且 CLI 查询确认存在。
- workflow 明确规定默认值，例如 `formType=task`、默认云发布、封面默认首图。
- 查询结果只有一个高度匹配候选，且该字段不会改变发布目标、账号或收费/交易类绑定。

自动选择后，Agent 应在面向用户的说明中说明来源和原因。

## 候选展示格式

展示候选时不要粘贴完整原始 JSON。优先使用稳定、可比较的字段。

### 账号候选

| 字段 | 说明 |
| --- | --- |
| 序号 | 供用户快速选择 |
| `platformAccountId` | 必须展示 |
| 名称 | `platformAccountName` / `name` / `nickname` / `remark` 中最清晰的值 |
| 状态 | `status` / `loginStatus`，说明是否在线或可用 |
| 平台 | 如 CLI 返回则展示 |

### 动态字段候选

| 字段 | 说明 |
| --- | --- |
| 序号 | 供用户快速选择 |
| ID | CLI 返回的稳定 ID |
| 名称 | 候选显示名 |
| 层级或类型 | 分类路径、音乐分类、商品类型、活动类型等 |
| 备注 | 匹配理由、平台限制、是否叶子节点 |

## 用户选择解析

- 用户可以用序号、稳定 ID 或完整名称选择。
- 如果用户回答仍不唯一，继续追问，不要猜第一项。
- 一旦用户确认，将所选候选的完整 CLI 返回对象作为字段来源，再按 schema 装配到 payload。
- 视频号剧集候选通过 `yxer query drama-tasks` 获取；确认后只写入 `yixiaoerId`、`yixiaoerImageUrl`、`yixiaoerName`，不把合集的 `raw` 结构带入 `drama`。

## 确认后的记录

进入写操作前，Agent 应在内部或 payload meta 中保留以下信息，便于排查：

- 被确认字段路径。
- 候选来源命令。
- 用户选择的序号或 ID。
- 最终写入 payload 的稳定 ID 或 key。
