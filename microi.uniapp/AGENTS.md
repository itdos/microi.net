# Microi UniApp Engineering Contract

This file applies to the entire `microi.uniapp` repository. AI coding tools and
human contributors must read it before changing code.

## Product Boundary

`microi.uniapp` is the standard native mobile client for Microi. The repository
also contains the delivered `xjy` customer profile. The default local profile is
`xjy` so a normal build must never reduce the current Jifuli experience.

Use these layers:

1. `src/platform/`, `src/components/mci-*`, and `src/pages/module/` are standard
   product code. They must not contain tenant table names, tenant field names,
   customer copy, tenant assets, or tenant routes.
2. `src/tenants/<tenant>/` contains customer-only modules, runtime behavior,
   form hooks, native-table hooks, presets, assets, and optional page code.
3. `profiles/<profile>/` contains brand, API, OsClient, features, routes,
   `pages.json`, and `manifest.json`.
4. `src/generated/` is generated by the profile scripts. Do not hand-edit it.

## Dynamic-First Rule

- Standard list/detail/edit pages must consume authorized `sys_menu`,
  `diy_table`, and `diy_field` metadata.
- Metadata must use `V8.FormEngine.GetDiyTableModel/GetDiyFieldList`, which
  wrap the cached FormEngine endpoints. Pages and controls must not query
  protected `diy_table/diy_field` through ordinary CRUD or scatter raw endpoint
  URLs.
- View configuration uses physical `sys_menu` fields such as `ViewSchema`,
  `EnableViewSchema`, `ViewSchemaVersion`, and `ViewConfigVersion`.
- `DiyConfig` on `sys_menu`, `diy_table`, or `diy_field` is retired. Do not read
  or write it.
- A backend field name, order, control, visibility, data source, or mobile list
  change must become visible after metadata cache invalidation without a new
  mobile release.
- Prefer `ViewSchema` and the generic module renderer. Add a tenant extension
  only when the workflow needs native capabilities or a customer-specific
  composition.

## Security And Actions

- Never execute arbitrary frontend V8 or use `eval`/`new Function`.
- Mobile actions use the whitelisted `ActionSchema`; complex logic runs in an
  ApiEngine and important validation remains in server-side form events.
- Every data request uses the real authorized menu context when one exists.
- Never trust role, scope, table access, or AI data permission supplied by the
  client.

## Tenant Extension Contract

Each tenant must implement:

- `business.js`: navigation groups, module presets, role presentation.
- `runtime.js`: customer-only summaries, native navigation, scan workflows.
- `form.js`: field actions, linkage, and submit extensions.
- `native-table.js`: customer-only relation filtering and save behavior.

Do not add `if (OsClient === ...)` branches to platform pages. Extend the tenant
contract or add a versioned standard protocol instead.

## UI And Performance

- Follow Microi.UI tokens, safe areas, skeleton states, empty/error states,
  reduced-motion handling, and 8px-or-less card radii.
- Third-party UI libraries are implementation details. Wrap them in
  `src/platform/ui/adapters/`; pages only use `mci-*` components.
- Keep first-screen requests bounded, cache by identity and schema version, and
  lazy-load related tables and tenant-only bundles.

## Merge-Friendly Workflow

- Keep changes scoped. Do not reformat unrelated files or overwrite another
  contributor's work.
- Add a new protocol field compatibly before removing an old path.
- Do not commit generated output for a non-default profile. The checked-in
  generated bridge must point to `xjy`.
- Run `npm run check:architecture` and `npm run check:ui` before merging.
- Changes to platform/dynamic rendering require both
  `npm run build:mp-weixin:standard` and `npm run build:mp-weixin`.
- Changes to Jifuli pages require `npm run visual:xjy`; native camera, location,
  payment, and destructive workflows still need device acceptance.

See `docs/architecture.md` and `README.md` for implementation details.
