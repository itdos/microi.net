# 需求方案按安装点位汇总成本

当前租户：集福鲤，`xjy`。需求方案表 `diy_kehufaxx`；安装点位表 `diy_anzhuang_dw`；关联字段 `AnzhuangdianweiId`。

## 行为

- 方案保留合作前的饮水方式、单台服务人数、设备数量与自动计算公式。新点位增删改不会替换现状人数或现状成本。
- 点位使用自己的型号、设备数量、人数、租赁单价、买断单价及滤芯费用，生成 17 个只读计算字段。
- 方案合作后字段汇总全部有效点位；原单台标签改为合计，买断设备费用按各点位单价乘数量后累加。
- `HesuanNS` 是统一试算年数；点位及方案的 `ShisuanNS`、`ShisuanNSMD` 继承它，不相加。修改方案年数会在同一事务更新点位结果。
- 方案比价信息中显示“合作前成本”“合作后成本（租赁）”“合作后成本（买断）”三个小标题。点位“设备报价与成本”默认展开。

## 计算口径

点位人数表示该点位总人数。单台年电费为人数 × 30 ÷ 数量，单台年水费为人数 × 2.4 ÷ 数量。租赁和买断的水电费均按人数自动计算。

租赁单台年度成本 = 单台水费 + 单台电费 + 租赁单价；点位年度总额 = 单台年度成本 × 数量；多年总额 = 点位年度总额 × 年数。

买断单台年度饮水成本 = 单台水费 + 单台电费 + 单台滤芯维护费；点位年度总额 = 单台年度饮水成本 × 数量；多年总额 = 买断单价 × 数量 + 点位年度总额 × 年数。购置款只计一次，不摊入年饮水成本。例如 2 台、单价 15,500、每台年维护费 1,940、水电费为 0、5 年：购置费 31,000、年饮水成本 3,880、多年累计 50,400 元。

点位水电费采用单台每年口径；服务费采用本点位所有设备每年合计，租赁为租赁单价 × 数量，买断为滤芯价格 × 数量。单台饮水成本使用水电单台值加服务费合计 ÷ 数量；点位年总额为单台水电费 × 数量＋服务费合计。方案直接累加各点位服务费，不再次乘数量；只有单台水电费、购置价在汇总时乘点位数量。年度总额与多年总额直接相加，年数不累加。缺失租赁报价或买断购置报价时，对应完整费用仍返回空值；买断年运行费可独立计算。方案按字段累加已有金额，空点位不抵消有值点位，全列都为空才返回空值。部分点位缺价时，方案显示的是当前已维护金额的合计。

现状人数表示单台服务人数，水电仍按单台计算。“当前服务成本（所有设备/年）”使用当前饮水设备数量 `DangqianYSSBSL`：老式开水机每台 500 元，其他方式沿用原规则。忽略历史设备方案数量 `ShebeiSL`。单台总成本使用单台服务费，所有设备总成本只乘一次现状设备数量；当前数量为 0 时服务费合计和总成本为 0。水电和服务费计算结果只读，打开历史方案时也重新计算预览。

## 后台资源

`manifest.json` 为新增点位字段的增量声明；`field-patches.json` 和 `layout-patches.json` 为已有字段的精确补丁，保留其他配置。然后依次应用 `cost-unit-patches.json` 和 `service-quantity-patches.json`，后者将服务费显示为相应设备年合计，并配置准确的单台/合计说明。

`scripts/build-proposal-cost-resources.mjs` 从 `src/tenants/xjy/proposal-cost-model.mjs` 生成方案、点位事件及比价接口源码。生成后通过当前租户 MCP 保存并回读，实际版本号由后台生成；不要把生成操作视为已发布。

点位保存前校验输入、合并旧数据并锁定父方案；保存后在共享事务重算父表合作后汇总。方案保存前统一年数并通过 `UptTableData(updates, V8.DbTrans)` 批量更新点位。兼容 `Insert/Update/Delete` 和旧 `Add/Upt/Del` 动作，不手动提交事务。

`add_datacopy` 的点位专用分支见 `point-copy-prefix.js`，通过正式表单事件复制点位，其他表原复制代码保留。小程序点位复制与批量配置原本已触发表单事件，继续使用原入口。

新增索引：`idx_proposal_point_parent_deleted (AnzhuangdianweiId, IsDeleted)`。读取全部点位使用参数绑定，不受列表 1000 条分页截断影响。不批量改写已有业务记录；历史方案打开时重新预览汇总，正常保存时写入派生值。
