# 集福鲤订单五状态规则

`Diy_Dingdan` 的状态文字统一为以下五项，沿用原数字状态值，避免破坏已有设备、售后任务和权限判断。

| 状态 | 数字值 | 规则 |
| --- | --- | --- |
| 待审批 | 1 | 新订单、原待审批和原驳回；驳回保留审批意见 |
| 进行中 | 2 | 原已审批；审批通过后按当前日期判断是否已经到期 |
| 已到期 | 7 | 服务结束时间或合同结束时间任一早于当天 |
| 终止待审批 | 5 | 原待审批作废；申请时保存服务端状态快照 |
| 已终止 | 4 | 原已作废或真实申请断约形成的合同已断约 |

空日期不参与到期判断，结束日期等于当天仍有效。日期不会再把合同改为已断约。已终止优先于已到期；待审批和终止待审批在每日校准时保持可办理。

终止申请驳回后，恢复申请前的业务状态，并按驳回当天的日期重新判断进行中或已到期；审批日志保留驳回意见。原作废批准后的设备和售后任务处理规则保持原流程。断约申请的生效节点沿用原业务事件，只增加订单已终止的同步。

服务端 `xjy-order-status-policy` 是统一判断接口。日期字段预览、订单提交校验、审批通过、终止驳回和每日任务使用同一规则。移动端 `order-status.mjs` 只用于页面预览，服务端保存结果为准。按钮沿用原 Id 权限；普通审批、终止申请和终止审批分别授权。

客户与订单统计按新状态过滤；设备详情继续在待审批和终止待审批阶段隐藏。售后任务自己的状态名称保持原定义。
