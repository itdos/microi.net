# 需求方案成本推荐

需求方案列表及客户详情的关联方案列表均沿用“一键比价”入口。结果页保留点位明细和成本对比，新增统一使用年数、需求基准、人工需求确认、租赁/买断排名及最低成本组合。

## 评价范围

- 默认以首个所选方案为需求基准，并用该方案的试算年数统一重算全部方案；支持1至100整数年，只影响本次预览。
- 业务人员先确认所选设备组合均满足客户实际需求。确认不自动证明设备性能，也不写入审批或设备验收记录。
- 系统要求客户相同，安装场所、点位用水人数及已填水质、打水、加热、水温、高峰开水量要求一致。点位顺序和多选值顺序不影响判断；设备型号、数量和价格可以不同。
- 缺少客户、点位、安装场所、正整数人数、正整数设备数量或设备信息时不参与推荐。
- 租赁须每个点位都有有效租金；买断须每个点位都有有效设备买断价和年滤芯费。明确填写0表示免费，空值不表示免费。部分点位缺价的汇总不会用于排名。
- 只比较同一周期内的累计成本：租赁为年运行费乘年数；买断为一次性设备款加年运行费乘年数。沿用已有水电费公式，不改写历史报价和主子表成本。
- 保留所有并列最低项，显示与下一档有效报价的差额。仅一个可评估方案或部分方案被排除时，明确提示结论范围，不宣称全部所选方案中的绝对最优。
- 不评价品质、售后、融资、维修、残值及未来价格变化。未配置的设备性能匹配仍需业务人员核验。

## 接口与兼容

`xjy_compare_customer_proposals` 保留 `Data[]` 及 `CostFields`，新增 `Data[].CostReview` 和 `DataAppend.Comparison`。参数 `Ids` 仍支持单方案预览；可选 `Years`、`ReferenceId`、严格布尔 `RequirementsConfirmed` 只控制本次分析。任何金额、客户、点位和需求均从授权记录回读，不接受客户端正文作为计算依据。部分方案无权访问时整次失败，不输出裁剪后的伪完整推荐。

原公式来源为 `proposal-cost-model.mjs`，推荐规则来源为 `proposal-cost-recommendation.mjs`。发布脚本用同一规则生成后端文本；通过 `--engine-only` 可仅生成比价接口，避免重写无关表单事件。
