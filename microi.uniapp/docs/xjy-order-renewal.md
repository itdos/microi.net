# 集福鲤小程序合同续签

订单详情的“相关订单”保存的是关系快照。新增、查看和编辑动作必须打开快照指向的真实 `Diy_Dingdan`，不能直接编辑 `diy_dingdanxq_relation`。

新增续签先调用 `xjy-order-renewal / Preview`，随后进入正常的原生合同新增表单，以该页面生成的真实草稿 Id 依次执行 `xjy-order-draft / Begin` 和续签 `Initialize`。合同与服务起止日期、联系人、地址、商品服务价格、安装位置等继续使用正常表单控件；已初始化的客户、来源订单和沿用设备身份不可更换。重复返回页面不重新复制明细，也不覆盖用户已调整的值。填写续约月数时按日历月计算到期日，仍可手动调整结束日期。

合同未保存时，商品、耗材和安装位置通过固定业务动作 `DraftRows / DraftRecord / DraftSave / DraftDelete` 读写。服务端只允许三个固定明细表，按真实父外键核定合同，并验证有效账号、角色菜单权限、本人草稿、商家、客户、状态和有效期。写入在共享事务中执行原生表单事件，界面不传入可信身份或跳过事件的开关。正式合同只收到明确的 `UseNativeQuery` 标记后才沿用原生数据路径；失败不能回退绕过校验。

沿用设备只引用原客户设备和原设备编号，不新增真实设备，不重写原设备的 IoT 正反向绑定。沿用安装位置隐藏关联、新增、解除 IoT 按钮，提供“查看沿用设备”入口。删除本次续签的沿用位置只移除本次合同引用。已买断设备默认仅收服务或换芯费用，硬件金额为零，服务单价可调整；其他收费范围按平台已有规则处理。

关闭未保存页面会取消本页面草稿；保存成功后以原生主表事务的 Commit 为准，客户端不再调用 Cancel。离线或取消请求失败时由既有服务端过期回收处理。

专项回归入口：`npm run check:xjy-order-renewal`。导航、表单 hooks 和生命周期用例覆盖新增、微调、重入、失败重试、分页、金额、来源保护及沿用设备。服务端事务与 IoT 保护回归位于客户业务源码自身的 `tests/order-renewal-draft-proxy.test.cjs`，不放入平台后端测试。界面验收使用 `npm run visual:xjy` 的本地模拟接口，正式合同保存、审批及真实设备操作仍需实际账号验收。

本次未修改 `Microi.Client`、`Microi.Server` 或数据库结构。业务引擎已通过集福鲤 MCP 同步并全量回读：`xjy-order-renewal-context v1.0.4`、`xjy-order-renewal v1.0.3`；2026-10-16 的插件同口径 `sync status --scope api` 为 0 差异。小程序源码和编译产物需要重新加载或通过微信渠道发布后才会替换旧页面。

首页“我的订单”始终进入主订单菜单。详情页的“相关订单”使用隐藏关系菜单，其 `DiyTableName`、移动字段和 `DiyTableId` 必须对应 `diy_dingdanxq_relation`。2026-10-16 排查发现关系菜单误写主表名，造成首页标题和永久表 Id 缓存串入子表；已纠正该菜单元数据。客户端改为按授权菜单当前快照推导表 Id，同表优先精确业务别名，显式子表菜单 Id 仍保留；菜单缓存升级为 v3 并按 API、租户、账号隔离。`check:menu-resolution` 同时覆盖污染旧缓存、刷新和两个入口各自的授权查询。
