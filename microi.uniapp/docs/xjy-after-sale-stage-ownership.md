## 生效范围

- 服务阶段继续使用 `ShouhouRYID`；待客服验收阶段使用 `HouxuFZRID`。新增任务按“任务手动指定 > 订单 > 客户”解析，并验证账号启用、商家一致、客服角色有效。客户验收仍由客户关联账号本人执行，不将客户账号当作内部任务负责人。

## 六项独立操作权限（后续迭代）

角色管理的“售后任务”菜单新增六个仅用于授权的独立按钮；它们不会在平台表单中额外显示操作入口。用户能否在小程序任务详情看到操作按钮，由服务端按任务状态、阶段负责人/商家范围、客户关联账号和下表权限共同计算，不能仅靠前端隐藏按钮。

| 操作 | 权限按钮 ID |
| --- | --- |
| 客服验收通过 | `56b9d9f5-667d-45d4-a4d4-17d9bf541172` |
| 客服验收退回 | `7e9589d9-e7b3-4870-a4d9-a614a48bfee9` |
| 客户验收通过 | `2860d95a-37d1-4069-8eea-4e27b44ac313` |

| 追加评价 | `cfc00d1c-3b37-4e11-98c7-e739d2cd81f2` |

- 关联客户账号本人仍按客户关联关系操作，不要求后台角色勾选；同一客户填写的多个关联账号均可操作，但同一任务的验收/首评/追评分别只能提交一次。
- 员工代办客户侧操作必须具备“售后任务读取”和对应的独立按钮权限，且与任务同商家；售后工程师或销售不会因为旧“用户评价”等同名按钮而自动获权。
- 当前仅为原有客服、客服主管及具备菜单读取的同商家总经理保留两项客服验收权限；四项客户侧代办权限默认不授予任何员工，需在角色管理中逐项开启。客服验收还需满足阶段负责人或主管作用域规则。
- 小程序“追加评价”改走 `shouhoudd_follow_up` 接口，旧平台验收入口改走 `task_acceptance`，普通表单编辑不得绕过六项权限直接改验收/评价字段。平台接口引擎和表单提交事件已保存到 `xjy` 在线租户；小程序源码尚未上传或发布。
- 回读旧平台按钮时发现“商家验收不通过”误传通过动作类型；已将该按钮的参数修正为商家退回 `3` / 客户不通过 `4`，仍由服务端逐项校验新权限。
- 代客户提交首评是否计入商家平均分尚待业务确认；**在确认前不要开启“客户评价”员工代办权限**。之前“不需要待客户验收的任务不参与评分分母”的口径不变。

回退时先停用六个新增角色按钮权限，再恢复 `shouhoudd_authorize_flow_action`、`shouhoudd_flow_capabilities`、`task_acceptance`、`shouhoudd_pingjia`、`shouhou_yanshou`、`Diy_ShouhouDD.SubmitBeforeServerV8` 的本次版本，并停用新接口 `shouhoudd_follow_up`；最后回退小程序本次页面/能力代码并核对线上菜单与角色授权。逐项恢复前必须备份当前资源，不能只撤销前端代码；历史验收、评价、日志与消息不能自动撤销。

本迭代已通过 `npm run check:ui` 和更新后的 `npm run check:task-post-service-permission`（含六项隔离、旧入口拦截及 Vue 模板编译），线上回读确认六个按钮、五个客服/主管/经理角色的两项客服验收授权、专用接口和表单服务端守卫。`cs新版tab` 任务只做了线上只读及拒绝路径验证，未改变其验收或评价。由于当前构建机器物理内存仅余约 1.7 GB，本迭代没有再次执行完整微信小程序构建或上传发布；这两项需在资源充足后补验收，不能把上文上一迭代的构建结果当作本迭代的构建结果。
