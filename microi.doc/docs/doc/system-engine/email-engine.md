## 安装和打开

1. 将平台后端更新到包含 `V8.Email` 的版本，确保各 API/任务节点运行相同能力。
2. 在吾码应用商城搜索 **邮箱系统**（AppKey：`mci-email`），安装或更新源码版应用。
3. 打开 **系统引擎 → 邮箱系统**。后台菜单地址为 `/mci-email`。
4. 首次安装后添加自己的邮箱，并执行一次连接检测和手动同步。

已有「邮件配置」菜单会迁移到这个入口，邮箱账号仍保存在原表 `mic_email_server`。
当前版本保留原邮箱配置的平台管理员权限，并按账号所有者隔离邮件。

## 添加邮箱账号

点击左侧「我的邮箱」旁的加号，或进入「管理邮箱 → 添加邮箱」。
系统弹出吾码表单引擎的账号维护窗口，分为账号信息、收发服务器和同步设置。

| 设置 | 填写方法 |
| --- | --- |
| 账号名称 | 自己容易识别的名称，例如「工作邮箱」 |
| 邮箱地址 | 完整地址，例如 `your-name@qq.com` |
| 服务商 | QQ、163、126、腾讯企业邮箱或自定义 |
| 邮箱授权码 | 在服务商处生成的客户端授权码；通常不是网页登录密码 |
| 收件/发件服务器 | 选择常见服务商后自动填入，也可以手动修改 |
| 自动同步 | 开启后按同步间隔收取，关闭后仍可手动收取 |

常见服务商的预填值如下，企业管理员自定义配置时以实际服务商要求为准。

| 服务商 | IMAP 收件服务器 | SMTP 发件服务器 | 默认加密 |
| --- | --- | --- | --- |
| QQ 邮箱 | `imap.qq.com:993` | `smtp.qq.com:465` | SSL/TLS |
| 163 邮箱 | `imap.163.com:993` | `smtp.163.com:465` | SSL/TLS |
| 126 邮箱 | `imap.126.com:993` | `smtp.126.com:465` | SSL/TLS |
| 腾讯企业邮箱 | `imap.exmail.qq.com:993` | `smtp.exmail.qq.com:465` | SSL/TLS |

使用 SMTP 587 的服务商请选择 STARTTLS。系统不支持明文连接。
授权码保存后按租户加密，编辑时留空保留已有值；列表和导出不返回授权码原文。

## 日常收发邮件

| 操作 | 使用方法 |
| --- | --- |
| 收取邮件 | 点击右上角「收取邮件」；选中全部账号时收取所有已启用邮箱 |
| 自动同步 | 在「管理邮箱」开启自动同步，在账号表单中调整间隔 |
| 阅读和搜索 | 从中间列表选择邮件，或搜索主题/发件人；支持未读筛选 |
| 写信 | 点击「写邮件」，填写收件人、主题和正文，可展开抄送与密送 |
| 草稿 | 点击「保存草稿」；离开写信区域时保存当前内容，可从草稿箱继续 |
| 回复或转发 | 在阅读区点击回复/转发，编辑内容后发送 |
| 附件 | 写信时添加附件；阅读时点击附件名称下载，单封附件总大小上限 10MB |
| 星标与已读 | 在阅读工具栏切换，远端 IMAP 状态同步更新 |
| 垃圾箱 | 将邮件移入服务商垃圾箱，不会清空整个邮箱 |

首次同步会先显示最新一批邮件，再分批补齐历史。几万封邮件需要一定时间，
可以继续使用工作台，并在通知中心查看后台任务状态。
正文按需下载，外部图片默认不自动加载。

发送成功提示表示发信服务器已接受邮件。若连接在投递期间中断，
邮件进入「发件箱」并显示待核对状态；请先检查已发送目录，避免重复发送。

## AI 与接口引擎

业务接口统一为 `/apiengine/mci-email`，使用当前登录的 DiyToken 和当前租户。
前端使用吾码 SDK 调用，账号密文不会下发到浏览器。

```js
// 查询自己的邮箱与目录
await microi.ApiEngine.Run('mci-email', { Action: 'Overview' });

// 手动同步：保留 RequestId，用于同一请求的恢复
await microi.ApiEngine.Run('mci-email', {
  Action: 'Sync', AccountId: accountId, RequestId: requestId
});
```

| MCP 工具 | 用途 |
| --- | --- |
| `microi_email_query` | 查询账号、分页邮件、正文、附件、连接和任务状态 |
| `microi_email_manage` | 保存账号/草稿、设置同步、移动邮件和设置标记 |
| `microi_email_send` | 发送已保存且经用户授权的草稿，绑定稳定草稿 Id |

邮箱 Skill 为 `email-engine`。AI 应先确认目标租户和账号授权范围，
只读取任务所需的邮件；只有用户授权发送时才调用发送工具。

<details>
<summary>开发者：接口、同步状态与源码扩展</summary>

接口引擎 `mci-email` 提供 `Overview / Accounts / Messages / Read / Attachment / SaveAccount /
Preferences / TestConnection / Sync / SyncStatus / SaveDraft / Send / Flags / Move`。

同步由 `mci-email-sync` 后台任务、`mci-email-sync-step` 持久批次与
`mci-email-auto-sync` 定时入口协作。后三个接口禁止直接 HTTP 调用。
账号配置在原表；`mci_email_folder` 保存目录游标，`mci_email_message` 保存邮件缓存与草稿。

协议原子 `V8.Email` 处理 IMAP、SMTP、MIME 和租户凭据加密；业务编排仍使用接口引擎。
完整参数参见 [后端 V8 → 邮箱协议](/doc/v8-engine/v8-server#邮箱协议-v8-email)。

商城升级管理核心接口，租户自定义逻辑放到 `mci-email-hook`，以 `CreateIfMissing`
交付，避免覆盖已有扩展。应用包不包含邮箱授权码、账号记录或邮件业务数据。

</details>
