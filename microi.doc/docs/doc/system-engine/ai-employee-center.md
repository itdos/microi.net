# AI 员工中心与吾码小龙虾

AI 员工中心为一人公司提供按岗位分工的 AI 团队：你给出目标、资料和验收标准，员工生成成果，你审核后再推进后续任务。吾码保存任务、权限和成果，吾码小龙虾提供本机 OpenClaw 员工节点。可在[官网 AI 应用详情](/app-detail.html?app=ai-employee-center)查看已发布版本、封面和体验入口。

::: tip 从一个任务开始
在应用商城安装 **AI 员工中心**，打开「工作台」，创建自己的十岗团队，再给产品经理分配一个小任务。当前 `v0.1.1` 交付可审阅的分析与草稿，所有完成状态都经过负责人验收。
:::

## 十个岗位如何分工

| 岗位 | 典型任务 | 主要成果 |
| --- | --- | --- |
| 经营助理 | 整理经营目标、会议记录、每日待办 | 执行摘要、决策建议 |
| 产品经理 | 把想法整理成需求与范围 | PRD、用户故事、验收标准 |
| 项目经理 | 拆解里程碑、依赖与风险 | 项目计划、风险清单 |
| 软件工程师 | 依据需求编写实现方案 | 技术设计、代码草稿、验证步骤 |
| 软件测试 | 设计功能、边界与权限测试 | 测试用例、缺陷与验收意见 |
| 财务专员 | 分析提供的收支和对账资料 | 对账差异、凭证清单、分析草稿 |
| 人事主管 | 编写岗位说明与入职流程 | 招聘需求、面试提纲、入职清单 |
| 市场运营 | 规划内容和营销实验 | 内容计划、营销文案 |
| 销售顾问 | 整理商机与客户需求 | 方案草稿、跟进计划 |
| 客户成功 | 整理问题与回复口径 | 回复草稿、FAQ、升级建议 |

岗位是独立的职责配置，不会创建十个管理员帐号。在「AI 员工」中可以调整名称、补充要求、模型名称、Agent 标识和在岗状态。执行中不能修改岗位，避免任务运行到一半改变职责。

## 安装与前置条件

1. 平台使用 MySQL，具备应用商城、持久后台任务和当前版本 AI 引擎。第一版按 MySQL 验证，其他数据库尚未适配。
2. 云端生成需要有效的在线 AI 授权、可用模型与额度。岗位模型留空时从当前用户获授权的目录选择；明确指定但不可用的模型不会被静默替换。
3. 管理员安装官方应用后，将「AI 员工中心」菜单授权给需要使用的角色。岗位、任务和成果按当前登录负责人隔离。
4. 小龙虾方式需要包含「AI 员工」页面的新版客户端及已初始化的 OpenClaw；云端应用安装不会自动升级桌面客户端。

应用包包含五张业务表、受管接口、写入保护、页面和菜单。用户首次创建自己的团队时幂等初始化十个岗位。包内不携带发布者的员工实例、任务、成果或密钥。

## 第一个可验收任务

在「任务协作」点击 **创建任务**：

| 输入 | 示例 |
| --- | --- |
| 负责员工 | 产品经理 |
| 任务名称 | 客户反馈小工具的最小需求 |
| 工作目标 | 整理不超过六条首版核心需求 |
| 验收标准 | 至少三个可验证条件，说明范围与未完成事项 |
| 参考资料 | 记录反馈标题、客户、优先级、状态；仅负责人使用 |
| 执行方式 | 云端 AI 草稿 |

保存后打开详情并派发。云端生成通过持久后台队列执行，关闭页面不会取消任务。入队请求超时后，刷新并使用同一任务继续提交，平台按幂等键去重。

成果进入「成果验收」后，可以查看正文、来源、SHA-256 和工作记录，下载 Markdown，再填写验收意见。实际用量缺失时显示未知，不按字符数捏造 Token 或费用。

## 多员工接力

1. 产品经理整理需求，你验收需求。
2. 软件工程师的任务选择产品任务为前置依赖，读取已验收需求后生成方案与代码草稿。
3. 软件测试任务依赖研发任务，生成针对性的用例和待执行清单。
4. 项目经理汇总已验收成果，整理风险与下一阶段计划。

每项任务最多选择五个既有前置任务。任务输入和依赖创建后保持不变；前置任务全部验收后才能派发。依赖按负责人权限读取，不能跨用户引用。第一版由负责人派发就绪任务，不自动启动整条链。

## 连接小龙虾节点

1. 在小龙虾「个人中心」登录与员工中心相同的吾码帐号。
2. 打开「AI 员工」，选择 **准备十岗配置**。新增按租户与负责人隔离的 Agent、目录和会话；保留默认 Agent 与模型密钥。
3. 到「服务管理」重启 Gateway，再连接节点。
4. 云端任务选择 **小龙虾员工 Agent**，派发后批准这一次执行，节点才会领取。
5. 成果回到云端验收。停止接单会保留正在处理的报告；取消具体任务请到云端操作。

第一版检查员工 Agent 的 `tools.deny` 包含 `*`，仅生成草稿。该限制来自真实配置，不依赖提示词。默认岗位标识如 `aie-product`，实际本机 Agent 自动附加负责人范围摘要。

从源码启动当前 OpenClaw `2026.3.11` Gateway 时，Node.js 需为 `22.12.0` 或更新版本。管理页面可打开不等于 Gateway 已启动；连接前应检查服务管理中的实际 Gateway 状态。本机设置了 HTTP 代理时，还需确认吾码 API 请求能正常到达所选地址。

节点只回传本次执行明确标记的最终正文。模型把写作过程混入响应时，这些文字不会作为成果保存；若模型没有返回有效终稿，任务会进入待人工核对的结果未知状态，不会把原始响应当作正式交付。

当前节点支持吾码官方 API 地址及其租户，自建 API 地址尚未加入节点配置；自建平台仍可使用云端草稿。节点 Token 仅用于当前进程，重启后重新连接，Gateway 密钥不上传到吾码。

::: warning Gateway 信任边界
Gateway HTTP 凭据具有管理范围权限，不能分发到员工浏览器。独立目录和会话不等于操作系统隔离；跨不可信租户时使用独立 Gateway、系统用户或容器。
:::

## 状态、重试与取消

| 状态 | 含义与处理 |
| --- | --- |
| 草稿 | 目标与标准已保存，尚未派发 |
| 待授权 | 等待负责人批准本次节点执行 |
| 待执行 | 等待后台或节点领取 |
| 执行中 | 持有有效租约，同一员工只执行一项任务 |
| 待验收 | 成果已保存，等待人工审核 |
| 已验收 | 负责人确认通过，可作为前置成果 |
| 已退回 / 执行失败 | 保留历史，可人工再派发，最多三次尝试 |
| 结果未知 | 调用中断或租约过期；先核对，不自动重试 |
| 已取消 | 拒绝迟到报告，已开始的模型调用可能仍计费 |

租约十五分钟，小龙虾每三十秒续租。失联任务可在详情核对过期执行，转为结果未知并释放员工。报告超时只重放原报告，不重新调用模型；本机进程崩溃可能丢失尚未提交的成果，需要人工核对。

云端在调用模型前独立保存开始标记，崩溃恢复不会再次发起同一尝试。它不能撤销已经发出的模型请求，也不代表外部系统的绝对一次执行。

## 第一版边界与扩展

第一版覆盖岗位、任务依赖、生成、执行授权、成果验收、审计和节点协议。资料来自任务输入与已验收成果，不自动取得整个公司数据库、邮箱或文件权限。

- 财务交付分析与对账草稿，不付款或报税。
- 研发和测试交付代码与用例草稿，没有执行证据不能称为测试通过或部署完成。
- 人事和销售不自动作出录用、辞退、薪酬或合同承诺。
- 营销和客服不自动向外部帐号发送或发布内容。

接入真实业务工具时，逐项增加服务端能力白名单、数据范围、动作审批、幂等与独立回读。企业共享知识库、团队成员授权、金额预算和自动排程是后续扩展，当前未实现。

## 开发与 MCP

业务接口 `mci-aie` 管理团队、任务、节点与验收；`mci-aie-draft` 通过持久后台任务运行。它们是应用拥有的 Managed 资源，升级会恢复官方源码，岗位偏好保存在员工记录中。

MCP 建模依次使用 `microi_get_db_schema`、`microi_get_manifest_schema`、`microi_plan_system`、`microi_generate_system` 和 `microi_validate_system`。后台使用 `microi_run_engine_background`，沿用幂等键，并独立回读业务成果。返回 TaskId 不代表已完成。
