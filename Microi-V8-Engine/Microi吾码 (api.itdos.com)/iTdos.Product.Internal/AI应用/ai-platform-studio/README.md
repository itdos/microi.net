# Microi吾码 AI 平台治理中心

面向 Microi 平台管理员、架构师和交付工程师的官方治理应用。它把门户、身份、访问、配置、功能开关、发布审批与断点回滚、服务韧性、Trace/日志、告警、资产协作和可恢复导入收敛到一套可安装资源包与宿主内微服务。

## 目录

- `.microi-micro-app.json`、`src/`、`microi.routes.json`：Vue 3 + Vite + TypeScript 宿主内多页面治理工作台及发布元数据。
- `build-manifest.mjs`：生成完整低代码系统 Manifest，作为表、字段、菜单、接口引擎与资源所有权策略的单一事实源。
- `engines/`：受管核心接口与租户扩展 Hook。核心接口使用 `Managed`，Hook 使用 `CreateIfMissing`。
- `system.manifest.json`：由构建脚本生成，供 MCP `microi_plan_system` / `microi_generate_system` 使用。
- `tests/`：前端契约、Manifest、所有权、计划哈希、审批、租约、幂等与安全边界测试。
- `dist/`：由当前目录构建的不可变微服务发布产物。

本目录同时是该 AI 应用的微服务源码根和官方应用商城发行源码根。界面、Manifest、接口引擎、资源策略、测试、构建脚本及商城上传素材必须在这里共同演进；工作区不得再创建平行的 `microi.apps/` 或嵌套第二份可编辑工程。

`package.json.version` 表示应用商城发行版本；`.microi-micro-app.json.version` 与 Manifest 版本表示不可变运行时/资源版本。只有运行产物或平台资源发生变化时才提升后两者，纯发行工程整理只提升商城版本。

## 菜单结构与定位

这不是给普通业务人员逐项操作的 40 套业务系统，而是平台管理员、架构师和运维人员使用的一套治理控制台。菜单固定安装到：

```text
系统引擎
└─ AI平台治理
   ├─ AI平台治理工作台（/micro-app/ai-platform-studio/overview）
   ├─ AI平台治理·门户项目
   ├─ AI平台治理·身份连接器
   ├─ AI平台治理·发布计划
   └─ ……共 40 个数据菜单
```

`AI平台治理工作台` 是统一操作入口，进入后可在 10 个治理页面间切换；40 个数据菜单按排序归为 9 个业务域：门户装配、身份目录、人群与授权、配置与灰度、发布治理、服务治理、可观测与日志、资产与协作、数据迁移。`配置` 类菜单负责定义规则，`审批/处置` 类菜单负责人工作业，`运行` 类菜单展示任务状态，`台账` 类菜单主要用于审计和排错。菜单用途的逐项清单以 `system.manifest.json.menuCatalog` 为单一事实源，并同步到官方文档与 Skill。

## 构建

```powershell
npm run build
```

该命令先生成并测试 Manifest，再执行前端类型检查、契约测试和微服务构建。生产发布仍须遵循 `microi_itdos` 的源码同步、不可变版本发布、商城包生成与远端回读流程。

## 安全边界

- 连接器只保存密钥引用，不保存密钥原文；标准 V8 代码不读取密钥明文。
- 身份同步先计划、再以计划哈希和幂等键执行；新账号默认停用，需管理员激活。
- 发布、回滚与告警写入均使用稳定哈希/事件 Id 防重，不能依赖单节点内存锁。
- 导入先预检和暂存，再由持久后台任务分片执行；失败可重试，回滚使用目标内容哈希保护后续业务修改。
- 所有扩展 Hook 首次安装后归租户维护，后续官方升级不覆盖。
- 当前 Manifest 固定为 40 张表、42 个菜单（1 个父菜单 + 1 个治理工作台 + 40 个数据菜单）、64 个接口引擎、1 个维护任务；微服务提供 10 条治理路由。
- 发布计划通过不可变审批、自动门禁、共享运行台账和单步检查点执行；失败必须保存事实并用同一幂等键续跑。
- 服务策略使用共享 Redis 原子许可与持久 Outcome 重建熔断；Trace、告警和日志归档均以共享事实支持多节点恢复。
