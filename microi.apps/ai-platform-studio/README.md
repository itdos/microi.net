# Microi吾码 AI 平台治理中心

面向 Microi 平台管理员、架构师和交付工程师的官方治理应用。它把门户、身份、访问、配置、功能开关、发布审批与断点回滚、服务韧性、Trace/日志、告警、资产协作和可恢复导入收敛到一套可安装资源包与宿主内微服务。

## 目录

- `build-manifest.mjs`：生成完整低代码系统 Manifest，作为表、字段、菜单、接口引擎与资源所有权策略的单一事实源。
- `engines/`：受管核心接口与租户扩展 Hook。核心接口使用 `Managed`，Hook 使用 `CreateIfMissing`。
- `microservice/`：Vue 3 + Vite + TypeScript 宿主内多页面治理工作台。
- `system.manifest.json`：由构建脚本生成，供 MCP `microi_plan_system` / `microi_generate_system` 使用。
- `tests/`：Manifest、所有权、计划哈希、审批、租约、幂等与安全边界测试。

## 构建

```powershell
npm run build
```

该命令先生成并测试 Manifest，再构建微服务。生产发布仍须遵循 `microi_itdos` 的源码同步、不可变版本发布、商城包生成与远端回读流程。

## 安全边界

- 连接器只保存密钥引用，不保存密钥原文；标准 V8 代码不读取密钥明文。
- 身份同步先计划、再以计划哈希和幂等键执行；新账号默认停用，需管理员激活。
- 发布、回滚与告警写入均使用稳定哈希/事件 Id 防重，不能依赖单节点内存锁。
- 导入先预检和暂存，再由持久后台任务分片执行；失败可重试，回滚使用目标内容哈希保护后续业务修改。
- 所有扩展 Hook 首次安装后归租户维护，后续官方升级不覆盖。
- 当前 Manifest 固定为 40 张表、40 个模块、64 个接口引擎、1 个维护任务；微服务提供 10 条治理路由。
- 发布计划通过不可变审批、自动门禁、共享运行台账和单步检查点执行；失败必须保存事实并用同一幂等键续跑。
- 服务策略使用共享 Redis 原子许可与持久 Outcome 重建熔断；Trace、告警和日志归档均以共享事实支持多节点恢复。
