# 自建数字人直播交付规范

## 先确定运行边界

用户要求免费、自建、不扣 token 时，默认采用用户自己的推理设备。模型仍处理 token，但本机计算没有供应商按次账单；硬件、电费、存储和吾码自身部署成本不能省略。禁止静默使用 MiniMax、吾码中转、Edge TTS、ZeroGPU 或在线试用作为本地推理成功的证据。

先盘点当前 MCP 的在线应用和实时 Schema，再读取目标应用源码。吾码负责话术、知识、角色、任务和记录，媒体运行时负责模型与音画。已有适合应用时扩展其页面，没有才创建 MicroService。业务表、字段、菜单和权限由 Manifest/应用包交付，不为数字人业务新增平台 Controller。

Windows 本机参考方案可采用 CPU 运行轻量 Qwen 与中文 TTS、CUDA 运行口型模型，并通过 WebRTC 向浏览器或 OBS 输出。若实现先生成片段再播报，应如实标注缓冲策略，不应描述成低延迟全双工数字人。输出帧率、模型生成帧率、首音延迟和总等待时间必须分开报告。

## 资源与模型

- 检查当前显卡、可用显存、内存、磁盘、已有进程和端口。不得为了腾显存结束未知进程。使用应用自己的 Python 环境，不修改共享环境。
- Windows 中文工作区中，部分原生 TTS / OpenCV 文件接口无法打开包含中文的绝对路径；优先在确定的运行目录中使用相对路径，并真实测试人像检测、语音生成与启动脚本，不能只测 Python 文件读取。
- 大文件固定官方仓库 revision、预期大小和 SHA-256；分段下载校验 Content-Range，支持原任务续传，下载完成后再加载。不把失败下载或仅安装依赖计为推理通过。
- 模型运行使用 `local_files_only` 和离线模式，无付费回退。运行时清除本进程继承的 HTTP/HTTPS/ALL proxy，避免本地代理成为外网旁路；随后限制外连。安装下载是独立过程，不全局修改用户代理。
- 权重许可、代码许可、人像/声音的使用权分别核对。研究测试素材仅用于本地研究验证，不放进公开应用包或默认当商业主播素材。
- 低端设备可以先合成片段、缓冲后播放；必须把该策略写入 UI 和文档。不能用静态图循环、音量驱动嘴型或测试桩冒充神经网络口型模型已经运行。

## 本机配对与吾码会话

- DiyToken 仍是吾码身份与权限入口。数据请求使用平台 SDK、当前租户和真实模块权限；不要把 DiyToken 发往本机模型或其它第三方。
- 若旧节点的 MCP 模块更新白名单不支持 ModuleEngineKey，不能以接口成功代替字段回读。可通过已有平台授权菜单接口的窄字段投影解析当前租户真实菜单 Id，携带 `_SysMenuId` 调用 FormEngine；不能写死发行租户 Id、放宽表权限或绕过标准 MCP 写入。
- 本机运行时只监听回环地址，另用随机配对码换取有期限、绑定 Origin 的本机会话。配对码、内部模型密钥和访问会话不出现在 URL、云端业务列或日志中。
- CORS 使用精确 Origin 列表，同时校验 Host；需要浏览器本地网络权限时明确给出诊断，不以通配 CORS 或绑定公网地址规避限制。
- 前端不开放任意 Endpoint、文件路径、命令、RTMP shell 参数或 Python 代码。模型输出只是待播报文本，不能执行 V8、SQL 或操作业务数据。
- 请求使用稳定 requestId；相同请求返回原任务，参数改变则拒绝。队列有界、停止可见、失败可诊断；状态与文件回读一致后才标为完成。

## 源码交付

- `.gitignore` 不等于 MCP 源码同步排除。必须在 `.microi-micro-app.json` 显式声明 `SourceExcludes`，排除虚拟环境、模型、凭据、人像、生成媒体、缓存和本机运行日志。
- 运行时源码、固定依赖、模型 lock、安装/启动/停止脚本和测试进入私有源码；编译产物进入公有运行目录。应用包不得带发布者的配对码或设备配置。
- 官网完整交付文档维护在独立菜单 `microi.doc/docs/doc/system-engine/digital-human-live.md`；`ai-engine.md` 的 `self-hosted-digital-human-live` 锚点保留入口链接。功能截图从真实页面组件采集并检查原始像素；使用隔离示例数据时必须在图内和文案中明确标注，不能把它称作线上租户数据或真实开播效果。
- MCP 已有应用发现、Manifest、元数据、源码同步和 v3 发布能力时直接复用，不为重复流程新增工具。交付记录明确四项状态：应用包、官网源码、Skills、MCP 复用/变更。

## 验收

1. 用 MCP 计划、dry-run、写入、结构回读，并验证业务新增/读取/修改/删除及权限拒绝。
2. 真模型生成中文音频，检测非静音、采样率与时长；真实口型模型生成帧，检查嘴部变化和图像输出。
3. 音频与视频探针校验时长、帧率、画面尺寸；WebRTC 接收者实际收到音视频，并检查浏览器播放。
4. 测试错误配对码、未授权请求、非白名单 Origin、请求重放冲突、队列上限、停止、模型缺失与外网拒绝。安全测试桩与真实模型验收分别记录。
5. 桌面/窄屏/深色界面、空态、失败态、素材 CRUD、菜单生命周期与输出页实际操作通过。
6. OBS 捕获和外部平台开播独立验收。OBS“媒体来源”循环播放已生成 MP4，只证明片段可被 OBS 录制；浏览器来源需要确认配对面板消失、服务端 WebRTC `peers` 大于 0，且 OBS 录制回读有真实音画，才能判为实时接入。未提供直播账号、推流地址或密钥时完成本机输出，明确外部直播未验证，不请求无关账号，不伪造“已开播”。

验收报告保留应用版本、模型 revision、真实设备、内存/显存峰值、生成帧率、等待时间和媒体摘要，不能只写“接口成功”。
