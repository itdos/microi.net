# Microi吾码解决方案与报价

生成客户可直接查看或发送的 `.docx` 方案报价，按用户要求同时导出正式 PDF。先基于真实需求和资料确定技术边界，再用清晰、工整的商务版式呈现价值、技术路线、总价、周期和限制条件。用户指定的提案主体、品牌、标题、页数、格式和商务数值优先于本 Skill 的默认模板；允许以合作方或客户品牌交付，仅在必要技术说明中注明所用框架。

## 工作流程

1. 读取需求、PDF、截图、现有 Word 和项目资料；不把尚未确认的硬件协议、第三方接口或平台能力写成已具备。
2. 提炼项目目标、核心范围、Microi吾码实现方式、关键技术路线、交付物、风险与前置条件。
3. 确定提案主体、项目名称、版本、日期、开发与实施周期、报价、优惠和有效期。用户已给值时必须原样采用；核对折扣计算、工期阶段及有效期起止口径，不擅自添加税率、付款比例或服务承诺。
4. 简单默认版式可使用 `scripts/build_solution_quote.py`；指定品牌、两页方案或图文布局超出脚本能力时，采用可编辑的 Word 排版实现，不让脚本默认值覆盖用户要求。
5. 渲染 DOCX 并逐页实际查看画面，检查字体、表格、换行、图文比例和溢出；需要 PDF 时从定稿 Word 导出并逐页复核 PDF 的页数、分页与内容一致。只有结构检查不能代替视觉验收；缺少可用渲染器时明确说明未完成的检查，不声称已经验证版面。

## 默认版式与视觉质量

- 页面：A4 纵向。
- 页边距：Word“窄”，上、下、左、右均为 `0.5 in / 1.27 cm / 720 DXA`。
- 布局：漂亮、工整、结构清晰，可快速扫读。小项目默认一页；用户明确要求两页或其它页数时按指定页数设计，每页具有完整主题和足够有效内容，不靠堆字、过小字号或大片无意义留白凑页数。
- 字体：中文优先 `Microsoft YaHei`，正文通常 10-11pt；标题约 20-24pt；章节标题约 12-14pt。根据页幅和实际渲染调整，先精简冗余或重排，不以缩小正文字号解决拥挤。
- 大标题默认：`Microi吾码 {系统名称} 解决方案与报价`；用户指定提案主体、标题或白标交付时按其要求替换，不强行添加吾码品牌。
- 默认品牌提案可使用副标题：`AI 深度融合 V8引擎 的低代码平台，官网：https://microi.net`；其它主体按受众采用项目价值副标题或省略。
- 标题下方放置版本、日期、开发周期、报价有效期；默认版本 `v1.0.0`，默认有效期 15 天。
- 默认使用克制的蓝色系，用户指定品牌时遵循其配色；统一标题层级、对齐线、间距和强调色。表格固定 DXA 宽度并设置单元格内边距，禁止依赖自动调整。
- 适当使用架构图、产品场景示意、流程图或时间轴表达关系和价值，配合短段落、信息卡和重点数字，避免整页密集文字或以装饰占据有效内容。AI 配图可选；技术关系和关键文字优先用清晰、可编辑的图形表达。示意图不得冒充已完成产品截图、客户现场或已验证架构。
- 页脚可放版本、日期、页码和提案主体联系方式；官网按品牌及用户要求决定，不重复正文报价。双页方案可将第一页用于目标与方案，第二页用于实施、报价与交付边界，保持视觉风格统一。

## 内容结构

按项目规模裁剪，但至少包含：

1. 项目目标：1 段说明客户要解决的问题和最终结果。
2. 解决方案：3-5 个具体范围，明确 Microi 表单引擎、V8 接口/事件、权限、PC 或移动端、第三方/硬件集成的分工。
3. 技术路线：用一行可读链路表达核心数据流；物联网项目必须区分“手机本地直连”和“公网云控”。
4. 交付范围：源代码/低代码元数据、接口、部署配置、联调、测试和简要操作说明。
5. 总价与周期：只展示市场预估总价、优惠总价和开发周期，不列模块价格明细。
6. 商务与技术边界：列出需求变更、第三方费用、硬件/云资源、协议资料、样机、账号资质等前置条件。

## 报价规则

- 不生成模块级价格表，不把各功能拆分报价。
- 同时展示：`市场预估价`、`优惠报价`、`开发周期`。
- 优惠报价应比市场预估价低；所有金额使用人民币并明确“总价”。
- 用户未提供价格时，可根据范围给出合理市场预估并标注为参考；硬件改造、协议逆向和第三方服务等不确定成本必须排除或写为“另行评估”。
- 不猜测含税状态、付款比例、质保年限或合同条款；用户未指定时写“以正式合同/确认需求清单为准”。

## Microi吾码技术表达

- 后台管理：优先使用表单引擎、菜单/权限和低代码元数据。
- 业务逻辑：使用 V8 接口引擎、表单事件、定时任务和缓存，不把项目专属逻辑写入平台通用层。
- 移动端：根据需求选择 UniApp/H5/微信小程序，并通过 HTTPS 调用后端接口。
- 物联网：推荐 `小程序 -> HTTPS -> Microi V8 API -> MQTT/TLS -> 网关 -> 设备协议`；保留设备本地安全联锁、离线保护和操作审计。
- 权限：菜单权限与接口业务权限同时设计；设备/客户数据必须做归属与行级校验。

## 生成脚本

准备 UTF-8 JSON 配置并运行：

```powershell
uv run --with python-docx -- python microi.skills/microi-solution-quotation/scripts/build_solution_quote.py `
  --input .tmp/solution-quote.json `
  --output "AI-Project/客户/项目/Microi吾码系统解决方案与报价.docx"
```

JSON 常用字段：`system_name`、`project_goal`、`solution_items`、`technical_route`、`deliverables`、`market_price`、`preferential_price`、`development_cycle`、`version`、`date`、`validity_days`、`boundary_note`。

## 工作区与交付检查

- 临时脚本、JSON、渲染图和 QA 产物写入仓库根目录 `.tmp/<任务标识>/`，按工作区规则登记并在完成后清理；正式 Word/PDF 保存在用户指定目录。
- 用户认为提取结果有长期价值时，将其整理到用户指定的项目目录，不留在临时目录。
- 标题、提案主体、日期、周期、报价和有效期符合用户要求；副标题、版本、品牌及联系方式按本次约定呈现。
- 没有模块明细价格，没有占位符，没有把未确认能力写成已交付。
- 页数符合本次要求；逐页确认无截断、重叠、孤行、超宽表格、过小字体或过密文字，图示、价格和联系人清晰可读。
- 最终回复链接正式 DOCX，以及用户要求的正式 PDF；不将临时 JSON、生成脚本、PNG 或仅用于 QA 的中间 PDF 当作正式交付物。
