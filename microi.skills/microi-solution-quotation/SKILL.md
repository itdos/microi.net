# Microi吾码解决方案与报价

生成客户可直接查看或发送的 `.docx` 方案报价。先基于真实需求和资料确定技术边界，再用紧凑商务版式呈现价值、技术路线、总价、周期和限制条件。

## 工作流程

1. 读取需求、PDF、截图、现有 Word 和项目资料；不把尚未确认的硬件协议、第三方接口或平台能力写成已具备。
2. 提炼项目目标、核心范围、Microi吾码实现方式、关键技术路线、交付物、风险与前置条件。
3. 确定项目名称、版本、日期、开发周期、市场预估价、优惠报价和报价有效期。用户已给值时必须原样采用。
4. 使用 `scripts/build_solution_quote.py` 生成 Word；复杂项目可按同一视觉规范扩展。
5. 把 DOCX 渲染为 PNG，检查页数、字体、表格、换行和溢出；修正后再交付。缺少 LibreOffice/soffice 时做结构检查，并在交付说明中明确未完成视觉渲染。

## 固定版式

- 页面：A4 纵向。
- 页边距：Word“窄”，上、下、左、右均为 `0.5 in / 1.27 cm / 720 DXA`。
- 布局：紧凑、商务、可快速扫读。小项目默认一页；不要用缩小到 9pt 以下正文的方式硬塞内容。
- 字体：中文优先 `Microsoft YaHei`，正文 9-10pt；标题 20-22pt；章节标题 10.5-12pt。
- 大标题：`Microi吾码 {系统名称} 解决方案与报价`。
- 副标题必须为：`AI 深度融合 V8引擎 的低代码平台，官网：https://microi.net`。
- 标题下方放置版本、日期、开发周期、报价有效期；默认版本 `v1.0.0`，默认有效期 15 天。
- 使用克制的吾码蓝色系；表格必须固定 DXA 宽度并设置单元格内边距，禁止依赖自动调整。
- 页脚可放版本、日期和官网，不重复正文报价。

## 内容结构

按项目规模裁剪，但至少包含：

1. 项目目标：1 段说明客户要解决的问题和最终结果。
2. 解决方案：3-5 个具体范围，明确 Microi 表单引擎、V8 接口/事件、权限、PC 或移动端、第三方/硬件集成的分工。
3. 技术路线：用一行可读链路表达核心数据流；物联网项目必须区分“手机本地直连”和“公网云控”。
4. 交付范围：源代码/低代码元数据、接口、部署配置、联调、测试和简要操作说明。
5. 总价与周期：只展示市场预估总价、优惠总价和开发周期，不列模块价格明细。
6. 商务与技术边界：列出需求变更、第三方费用、硬件/云资源、协议资料、样机、账号资质等前置条件。

## 报价规则

- 不生成模块级价格表，不把各功能拆分报价。
- 同时展示：`市场预估价`、`优惠报价`、`开发周期`。
- 优惠报价应比市场预估价低；所有金额使用人民币并明确“总价”。
- 用户未提供价格时，可根据范围给出合理市场预估并标注为参考；硬件改造、协议逆向和第三方服务等不确定成本必须排除或写为“另行评估”。
- 不猜测含税状态、付款比例、质保年限或合同条款；用户未指定时写“以正式合同/确认需求清单为准”。

## Microi吾码技术表达

- 后台管理：优先使用表单引擎、菜单/权限和低代码元数据。
- 业务逻辑：使用 V8 接口引擎、表单事件、定时任务和缓存，不把项目专属逻辑写入平台通用层。
- 移动端：根据需求选择 UniApp/H5/微信小程序，并通过 HTTPS 调用后端接口。
- 物联网：推荐 `小程序 -> HTTPS -> Microi V8 API -> MQTT/TLS -> 网关 -> 设备协议`；保留设备本地安全联锁、离线保护和操作审计。
- 权限：菜单权限与接口业务权限同时设计；设备/客户数据必须做归属与行级校验。

## 生成脚本

准备 UTF-8 JSON 配置并运行：

```powershell
uv run --with python-docx -- python microi.skills/microi-solution-quotation/scripts/build_solution_quote.py `
  --input .tmp/solution-quote.json `
  --output "AI-Project/客户/项目/Microi吾码系统解决方案与报价.docx"
```

JSON 常用字段：`system_name`、`project_goal`、`solution_items`、`technical_route`、`deliverables`、`market_price`、`preferential_price`、`development_cycle`、`version`、`date`、`validity_days`、`boundary_note`。

## 工作区与交付检查

- 临时脚本、JSON、渲染图和 QA 产物必须写入仓库根目录 `.tmp/`，禁止创建根目录 `tmp/`。
- 用户认为提取结果有长期价值时，将其整理到用户指定的项目目录，不留在临时目录。
- 大标题、副标题、版本、日期、周期、市场预估价和优惠报价全部存在。
- 没有模块明细价格，没有占位符，没有把未确认能力写成已交付。
- 小项目只有一页；无截断、重叠、孤行、超宽表格和过小字体。
- 最终回复仅链接正式 DOCX，不链接临时 JSON、生成脚本、PNG 或 PDF QA 文件。
