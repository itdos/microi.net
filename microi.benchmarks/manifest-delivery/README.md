# Manifest 声明交付的可复现检查

本目录检验真实 MCP 注册处理器的写前校验、会话引用、关系解析、微服务绑定和独立验收回执。
客户端边界使用确定性替身，**不连接数据库、不调用模型，也不是远端业务 E2E**。
它回答“非法声明会不会被忽略、先写一部分或后写覆盖”，不以 JSON 能解析代替安全落地。

## 从公开源码复跑

建议使用受支持的 Node.js 22 或 24；本机另保留 Node 20.20 兼容运行记录。公开仓内包含所需的 `microi.mcp` 源码与锁文件：

```sh
cd microi.mcp
npm ci --ignore-scripts --no-audit --no-fund
cd ..
node microi.benchmarks/manifest-delivery/verify.mjs --out /已有目录/新的结果.json
```

输出文件拒绝覆盖，省略 `--out` 则只输出 JSON。报告绑定测试清单、平台/Node/架构、
完整 `microi.mcp/src` 文件成员清单、原始字节与统一 LF 的源码 SHA-256、
`package.json`、锁文件、`tsconfig.json`、运行器本身、执行前后输入一致性、完整计数和 TAP 摘要。
退出非零、少于责任用例数、零测试、跳过、取消、待办和计数缺失都失败关闭。

## 完整 MCP 离线回归

默认入口继续执行五个 Manifest 责任测试文件，至少 60 项。完整检查使用同一个运行器，
从完整源码快照自动发现所有 `src/**/*.test.ts`，不依赖容易漏项的手工测试命令：

```sh
# 安装依赖同上；OpenSSL 须位于当前进程 PATH 中。
openssl version
node microi.benchmarks/manifest-delivery/verify.mjs --suite full --out /已有目录/新的完整结果.json
```

完整模式至少要求 355 项成功且没有失败、跳过、取消或待办；实际测试文件和计数写入结果，
不能把 60 项子集标成完整通过。测试包含本机临时 HTTP/TLS 服务、文件和内存客户端夹具；
无需业务租户数据库或付费模型，也不证明远端数据库执行、浏览器验收或认证。
运行器串行执行，单个 Node 测试进程堆上限 256 MB，完整模式总超时 5 分钟。

运行器 1.2.0 将输入绑定从九个指定文件扩为全部源码成员，执行中新增、删除或修改间接源码，
以及修改编译配置、依赖声明、锁文件或运行器都拒绝通过。`sources` 保存相对文件名与单文件摘要；
`sourceTree` 对按相对文件名排序的完整成员及摘要再计算 SHA-256，`inputFiles` 列出全部绑定输入。
原始摘要用于核对原始字节，统一 LF 的摘要用于比较跨系统换行差异；结果不含本机绝对路径或原始日志。

公共工作流保留 Linux/Windows × Node 22/24 的四组合约检查，并增加 Ubuntu / Node 24 的完整离线作业，
明确检查 OpenSSL、执行类型检查，再调用完整模式。工作流配置本身不是运行成功证据；
以具体提交的作业状态与脱敏 JSON 为准。源码回归、依赖公告检查和目标环境兼容验收各自独立。

本机 [Windows / Node 24.19.0 完整模式实际记录](results/2026-10-26-windows-node24-full-protocol120.json)
为 **356/356**，零失败、跳过、取消或待办；自动发现 58 个测试文件，绑定 89 个源码成员，
源码、依赖和编译配置执行前后一致。相较下文保留的 355 项历史记录，自动发现补入了原手工命令
漏列的 `job-runtime-tools.test.ts`，不把这一项计数变化解释成新增后端能力。
这条记录只覆盖所列 Windows 环境；Ubuntu 完整作业仍以对应提交的公共 CI 实际结果为准。

运行器 1.2.1 增加受限失败定位：最多记录 20 个已知测试文件的相对路径；标题只接受绑定源码中
可直接识别的静态测试名称，最多 200 个字符。动态标题、错误正文、参数、绝对路径和堆栈不进入报告，
无法安全对应的失败只记录空文件名。该诊断不改变任何测试断言、通过门槛或失败状态。
GitHub Actions 失败时也将同一受限定位写为 check-run 错误注解，并转义命令控制字符；
注解不包含错误正文，可先用公开检查信息定位，详细复现仍使用绑定提交与源码。

## 原问题和修复

旧的兼容读取会丢弃 `null`、字符串及空对象等错误资源；错误的集合类型也可能被当作未声明。
同一声明内重复表名、字段名或接口 Key 没有整体拒绝，可能导致前项写入或后项覆盖。
新增 11 项回归中，旧实现 9 项失败、2 项兼容检查通过；修复后这 11 项及直接相关回归全部通过。

新预检在兼容归一化之前核对原始声明，错误只返回原始项路径和固定原因；
合法的局部更新、相同大小写别名和不同表的同名字段保持兼容。
该门禁不代替服务端权限、跨资源事务或写后回读；网络错误及实际执行中失败仍须核对远端状态。

责任源码为 [`manifest-preflight.ts`](../../microi.mcp/src/manifest-preflight.ts)
与正式 [`advanced-tools.ts`](../../microi.mcp/src/advanced-tools.ts)，回归在相邻 `*.test.ts`。
工具发现可读取 `microi_get_manifest_schema.declarationPreflight.version=1`。
源码、打包工具、已加载 MCP、平台后端和客户安装是不同阶段，不能因源码存在声称旧进程已升级。

公开 CI 的系统/Node 组合以实际运行结果为准；Linux 或 Windows 上的 MCP 合约检查
不能当作后端数据库、CPU/OS 全矩阵或第三方认证。

## 运行器版本与实际结果

[Windows / Node 20 的首次记录](results/2026-10-26-windows-node20.json)使用运行器 1.0.0。
首次公开矩阵中，Node 22 两系统通过，Node 24 两系统失败；本机 Node 24.22.1 复现了
“子测试退出 0，但总账无法解析”的同一情况，没有把未知计数当作成功。

原因是 Node 23 起非 TTY 默认报告器由 TAP 改为 spec，参见[官方说明](https://nodejs.org/docs/latest-v24.x/api/test.html#test-reporters)。
1.0.1 明确指定 TAP，并核对运行器本身和被测源码的前后哈希；完整计数及所有失败/跳过门槛保持不变。
旧失败及旧结果保留，后续以绑定实际提交的公共 CI 结果判断组合是否通过。

本机 Node 24 的[修复前记录](results/2026-10-26-windows-node24-before.json)保留未知计数和失败退出；
[修复后记录](results/2026-10-26-windows-node24-after.json)为 54/54，通过显式 TAP 输出获得完整计数。
两者使用相同正式处理器与责任测试，运行器版本和哈希分别记录，不能把格式修复解释为新增业务覆盖。

1.0.2 另绑定 MCP 的 `package.json` 与 `package-lock.json`，依赖声明或锁文件在执行中变化也拒绝通过。
依赖升级后的 [Node 20](results/2026-10-26-windows-node20-protocol102.json)
与 [Node 24](results/2026-10-26-windows-node24-protocol102.json) 记录均为 54/54。
依赖安全回归和完整 349 项 MCP 回归单独列在[依赖核验](../compatibility/README.md#2026-10-26-mcp-生产依赖公告修复)，不混入本运行器的责任计数。

## 权限引用与验收协议修复

运行器 1.1.0 将责任检查从 54 项扩展到 60 项，继续绑定相同正式处理器、测试与依赖。
本机 [Windows / Node 20 实际结果](results/2026-10-26-windows-node20-protocol110.json)为60/60，源码与依赖前后哈希一致。
新增六项行为回归覆盖未声明名称、名称歧义、无效/冲突权限字段、保存成功却缺 Id、
原有合法权限兼容及不完整验收回包；在修复前的 29 项定向检查中 5 项失败，修复后 29/29 通过。

权限名称必须唯一引用本次声明；已存在资源使用真实回读的 Id。整批权限引用先解析，
缺 Id 时在第一笔权限写入前停止，不回退管理员、不丢弃未解析菜单；已保存的角色/菜单
仍需回读，不声称自动回滚全部资源。省略角色的管理员默认约定和显式空菜单清理保持兼容。

生成和独立验收都要求 `Code=1`、布尔 `Data.Passed=true`、`Errors` 缺省或为空数组。
回包缺失或矛盾时失败并保留诊断，不能靠单项 Banner 回读补成整体验收成功。

同一源码的完整 MCP 检查为 **355/355**，零失败/跳过。首次全量运行有一项真实 TLS
测试因测试进程找不到 OpenSSL 失败；配置已有 OpenSSL 的进程 PATH 后原断言通过，
没有删除或跳过证书测试。正式检查无需业务数据库或付费模型。

公共 CI 保留各系统/Node 作业日志，并将本运行器的脱敏 JSON 保存为 Artifact 90 天。
GitHub 附件下载按站点登录规则执行；需要匿名复跑时使用上面的源码命令。
这些结果不代表完整业务交付、目标数据库适配或已安装旧 MCP 进程的行为。
